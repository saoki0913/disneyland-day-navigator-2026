## GitHub push → Cloudflare Pages 自動デプロイ（無料・既存サービス分離）

- GitHub の本番ブランチ `main` への **push** で `.github/workflows/verify.yml` が起動し、単体テスト76件とモバイルE2E44件を実行します。
- **検証が成功した最新コミットのみ** `.github/workflows/deploy-pages.yml` が起動して、本番 `https://dl-navi-1031.pages.dev` にデプロイします。失敗したテストや古いコミットは公開されません。GitHub Actions の `workflow_dispatch` からプレビュー/本番を手動選択することもできます。
- Cloudflare と GitHub のネイティブ Git 連携は使いません（Cloudflare Git installation が 8000011 で失敗するため）。代わりに公式サポートの `wrangler pages deploy public --project-name dl-navi-1031 --branch main` を使います。
- **初回に1回だけ必要**：Cloudflare ダッシュボードの API Tokens で、対象アカウントの `Account › Cloudflare Pages › Edit` のみを許可したトークンを発行し、この GitHub リポジトリの `Settings › Secrets and variables › Actions › New repository secret` に **`CLOUDFLARE_API_TOKEN`** として保存します。Cloudflare のアカウントIDはワークフローで既存の対象アカウントに固定しているため、Secret は不要です。トークンを git、チャット、ログに貼らないでください。
- Secret 未設定の場合、自動デプロイのジョブが明確なエラーで失敗し、現在公開中のアプリはそのまま動きます。
- 本番デプロイは **既存の `dl-navi-1031` Pages** だけです。`mogup-api`、`career-compass-web-production`、`career-compass-web-staging`、`usa-trip-disney-day-1031`、他の Pages、DNS、ルート、カスタムドメイン、他サービスの環境変数・シークレット・課金設定には触れません。
- このリポジトリは公開設定で、GitHub Actions の通常の `ubuntu-latest` ランナーは無料。Cloudflare Pages も Free 枠内で運用します（月500ビルドが上限、Functionsはアカウント共通のWorkers無料枠を使用）。有料枠の有効化やプラン変更を行う設定はありません。Free枠を超えた際の実行可否はCloudflareの制限に従います。

## 画面と使い方

| タブ | できること |
|---|---|
| **いま** | 次に行く場所のカード（小さな写真・待ち／徒歩／終わる時刻・理由タグ・「歩く→待つ→乗る→余裕」の時間バー）、このあと、ほかの候補（待ち短い／近い／人気）、現在地 |
| **プラン** | プランは保存されたもので、勝手には変わらない（タブを開く・時間の経過・待ち時間の更新・GPSでは組み替えない）。作り直すのは「更新」「乗った」と、条件・順番・ごはん/ショーを変えたときだけ。2人共有では保存したプランそのものを共有するので、2台で同じプランになる。開くとすぐタイムライン（上に1行の要約と「条件」ボタンだけ）。「乗った」を押すとその時刻・その場所から残りのプランを自動更新（最新の待ち時間も取得）。作り直し・別の時刻から作る・条件のまとめはタイムラインの下。「条件を変えてプランを作る」。タイムラインの待ち時間は**いまの実測（LIVE）**を表示（予定時刻の予想と大きく違う場合は併記）。≡ をドラッグして**乗る順番を入れ替え**可能（いまの画面の「次」にも反映）。「作り直す」パネルに、何を使って作り直すか（開始時刻・待ち時間の鮮度・済み件数・現在地）と結果（順番変更／追加／外れた）を表示。1画面の条件ビルダー：ペース（ゆったり／ふつう／たくさん）、混雑（並べる時間 30／60／90分）、動線（歩く量）、乗りたいもの（タップで 絶対乗る→乗らない→おまかせ）、ごはん（お店と時間）、見たいショー（回）。下の大きなボタンに予想の乗り物数をリアルタイム表示。閉園までのタイムラインと ○ チェック |
| **マップ** | 待ち時間色分けのピン（再描画せず差分更新・ズーム中の更新は後回しにして消えないように）、食事・ショー、現在地（「現在地を表示」ボタン）、次の目的地への点線。下端の1行バー（行き先・徒歩・待ち・ルート）だけで地図を広く使える |
| **探す** | 乗り物／食事／ショー／限定 の4区分。食事は「食べたいもの」検索（キーワード＋候補チップ、言い換えにも対応）で、該当メニューを強調して現在地から近い順に表示。「マップ」で該当店だけピン表示。一覧・フィルタ・並べ替え、詳細シート（「絶対乗る／おまかせ／乗らない」もここで切替）、ショーの回選択と夜の動き方 |

**プランの編集（2026-10-31 追加）**
- プランは「順番」として保存。「乗った」では順番を変えずに時刻だけ更新（完了した項目が消えて、残りが詰まる）。
- 並べ替え：≡ をドラッグ（乗り物・ごはん・ショー）。ごはんは置いた位置で時刻が決まる。ショーは開演時刻固定で、間に合わない順番なら警告だけ出す（勝手に並べ替えない）。
- 鍵ボタンで乗り物の位置を固定。「更新」や条件変更で作り直しても、固定した乗り物はその位置のまま。
- 「編集」で × 削除、「＋乗り物・ごはん・ショーを追加」で自由に追加（動線のいい位置／次に行く）。乗り物の詳細からも「プランに追加／次に行く」。
- 食事にかける時間を設定可能。条件ビルダーに「次に行きたいところ」。
- いま タブ：一番上に次の行動、その下に細い進み具合の帯（タップで詳細）、ほかの候補。休止中など行動不要の注意は1回だけスナックバー表示、「再開」「空いてきた」だけ画面に残る。現在地は設定へ移動。

当日の流れ：開いたら「いま」の大きなカードの通りに動く → 乗ったら画面下の大きな「○○ 乗った」→ 次のおすすめが自動で更新。

- **完了の記録**：押すと即完了（トーストで取り消し可）。完了したものはプランタブの「済み」に時刻つきで残り、
  タップすると確認してから未完了に戻せる（戻した後もトーストで再び完了にできる）。
- **再開・急減アラート**：休止していた施設の再開や、人気施設の待ち時間の急減（15分以上かつ3割以上）を画面上部に表示。
  「行く！」で次の行き先に固定。Androidは振動あり（iPhoneのSafariは振動非対応）。
- **待ち時間の推移**：アプリが取得した今日の実測値を端末に記録し、一覧に小さな折れ線＋↘↗、詳細に推移グラフ（推定は点線）を表示。
- **片手操作**：「乗った」「別の候補」は画面下に固定の大ボタン。
- **設定**：右上の歯車。現在地（GPS）のオン／オフ、待ち時間の更新、記録のリセットだけ。出典・テスト時刻・ホーム画面に追加の手順は「詳細」に格納。
- **デザイン**：絵文字は使わず線アイコン。iPhone SE（375×667）でも文字が切れないよう、名前は「・」の位置で改行。
- **写真**：Wikimedia Commons から実際のディズニーランドの施設・店舗・ショーの写真をサーバーが検索（他パーク・ロゴ・小画像は除外、
  作者・ライセンス表示）。見つからなければ Wikipedia の記事画像 → イラストタイルの順に代替。

## 2人で共有

設定の「2人で共有」またはプランタブ下の「2人で同じプランを使う」→「共有を始める」で共有リンク（8文字コード）を作成し、相手に送る。
相手がリンクを開くかコードを入力すると参加。どちらかが「乗った」・順番・条件・ごはん/ショー・手入力の待ち時間を変えると、
もう1台も自動で更新（表示中は20秒ごとに確認、変更直後に送信）。「乗った」は合算、取り消しは新しい方が優先、設定は最後に変えた方が優先。
保存先は Cloudflare Workers KV（`dl-navi-1031-share`、バインディング `SHARE`）。保存するのはプランと記録のみ（位置情報は送らない）、7日で自動削除。

## データの扱い（偽装しないためのルール）

- **待ち時間**：ThemeParks.wiki（主）→ 失敗時 Queue-Times.com（予備）。Pages Function がエッジで60秒キャッシュし、
  画面表示中は3分ごとに自動更新。表示ラベル：`LIVE`（外部提供値）／`手入力`（公式アプリを見て入力）／`推定`（過去傾向の計画用の値）。
  15分以上古いデータは使わず推定に切り替え、バナーで明示。
- **ショー時刻**：APIから取得できればそれを使用（「APIの公式時刻」）。取得できない場合は事前情報として「要確認」と表示。手動修正可。
- **座標**：ThemeParks.wiki の施設座標を使用。取得できない場合は概略位置であることを表示。
- **徒歩時間**：直線距離×1.4 ÷ 分速70m の目安。
- **道案内（ルート）**：「ルート」は Google マップの徒歩ルートを開く（スマホのGPS現在地を出発点に指定）。アプリ内マップの「地図で見る」は目的地と現在地を点線で結んで表示。
- **一時休止**：休止中（DOWN）のアトラクションはタイムラインから外して「再開待ち」に表示し、再開を検知したら自動でプランに戻す。
- **位置情報**：「現在地を使う／現在地を表示」を押した時（または既に許可済みの場合）のみ取得し、端末内の計算にのみ使用（サーバー送信なし）。常時追跡（watchPosition）はせず、画面表示中だけ1回取得をマップでは60秒、他のタブでは3分に1回まで。
- **写真**：Wikimedia Commons（実物の写真・作者とライセンス表示）→ Wikipedia → イラストタイル。
- **進捗**：ブラウザの localStorage に保存（リロードしても保持）。

## 最適化アルゴリズム（概要）

`public/js/engine.js`（DOM非依存・テスト済み）

1. 次の固定予定（食事・ショー）までに「移動＋待ち＋乗車＋次の予定地点への移動」が収まるアトラクションだけを候補にする。
2. スコア = 人気 + ユーザー優先度 + 必須ボーナス（残り時間が少ないほど増加）− 待ち時間×重み − 徒歩×重み
   ＋「いつもより空いている」ボーナス ＋「この後混む」ボーナス。重みはプランごとに異なる。
3. 必須（スター・ウォーズ2施設）は休止中でも除外しない。入りきらない場合は、任意の予定（おやつ休憩・カヴァルケード）を
   後ろにずらす/別の回にする/見送る、ショーの場所取りを短縮する、閉園までに列に並ぶ、の順で救済し、理由を表示。
4. プランタブはこの推薦を閉園まで前向きにシミュレーションしたもの（30分以降は推定待ち時間を当日の混雑比で補正）。
