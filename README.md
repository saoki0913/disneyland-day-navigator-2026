## GitHub push → Cloudflare Pages 自動デプロイ（無料・既存サービス分離）

- GitHub の本番ブランチ `main` への **push** で `.github/workflows/verify.yml` が起動し、単体テスト120件とモバイルE2E70件を実行します。
- **検証が成功した最新コミットのみ** `.github/workflows/deploy-pages.yml` が起動して、本番 `https://dl-navi-1031.pages.dev` にデプロイします。失敗したテストや古いコミットは公開されません。GitHub Actions の `workflow_dispatch` からプレビュー/本番を手動選択することもできます。
- Cloudflare と GitHub のネイティブ Git 連携は使いません（Cloudflare Git installation が 8000011 で失敗するため）。代わりに公式サポートの `wrangler pages deploy public --project-name dl-navi-1031 --branch main` を使います。
- **初回に1回だけ必要**：Cloudflare ダッシュボードの API Tokens で、対象アカウントの `Account › Cloudflare Pages › Edit` のみを許可したトークンを発行し、この GitHub リポジトリの `Settings › Secrets and variables › Actions › New repository secret` に **`CLOUDFLARE_API_TOKEN`** として保存します。Cloudflare のアカウントIDはワークフローで既存の対象アカウントに固定しているため、Secret は不要です。トークンを git、チャット、ログに貼らないでください。
- Secret 未設定の場合、自動デプロイのジョブが明確なエラーで失敗し、現在公開中のアプリはそのまま動きます。
- 本番デプロイは **既存の `dl-navi-1031` Pages** だけです。`mogup-api`、`career-compass-web-production`、`career-compass-web-staging`、`usa-trip-disney-day-1031`、他の Pages、DNS、ルート、カスタムドメイン、他サービスの環境変数・シークレット・課金設定には触れません。
- このリポジトリは公開設定で、GitHub Actions の通常の `ubuntu-latest` ランナーは無料。Cloudflare Pages も Free 枠内で運用します（月500ビルドが上限、Functionsはアカウント共通のWorkers無料枠を使用）。有料枠の有効化やプラン変更を行う設定はありません。Free枠を超えた際の実行可否はCloudflareの制限に従います。


## パークの切り替えと日程

- 画面上部の **「ランド｜カリフォルニア」** で切り替え（ページを読み直します）。選んだパークを覚えておく。
- **日付によらず使える**：プランの日付はアナハイムの「今日」。先の日付を日程で選んだときだけその日（過ぎたら今日に戻る）。
  日付が変わって開くと、前日の「済み」・順番・保存プランは片付けて新しい1日に（絶対乗る・ごはん・ショー・ペースなどの好みは残す。前日の記録は端末内に `…:log:<日付>` で保管）。
- 選択中のパークをもう一度タップ、またはプランタブ上部の日程行・設定から **日付・入園・退園時刻** を変更。プランは入園〜退園の間で組み直し、退園後のごはん・ショーは外して表示。
- 進捗・プラン・日程はパークごとに別保存（ランドの記録はそのまま）。2人で共有中なら、同じコードのままパークごとに別の共有プランになります。
- データは `public/js/parks/dl.js`・`public/js/parks/dca.js`。`public/js/data.js` が選択中のパークを読み込みます。
- API（`/api/live`・`/api/meta`・`/api/photos`・`/api/share/:code`）は `?park=dca` でカリフォルニア・アドベンチャー。指定なしはランド（従来通り）。
- カリフォルニアの初期値（しおり通り）：11/1 8:00〜21:00、絶対乗る＝ラジエーター・スプリングス・レーサーズ、ランチ12:00、
  18:30 ご褒美ディナー（ランプライト・ラウンジほか、パーク内／ダウンタウン・ディズニーの候補から選択）、ワールド・オブ・カラー（時刻は要確認・APIの公式時刻に自動置換）。
- マップ下の「次の行き先」／ルートは「いま」のカード（＝保存したプランの次の行き先）と同じ行き先。マップを開いたままでもプランが変わると追従します。

## デザイン

Park Blue（ロイヤルブルー＋空色、白い角丸カード、フォントは M PLUS Rounded 1c）。幅320〜430pxの全画面で文字が切れないことを自動チェック。

- **ヘッダー**：パークのシルエットのイラスト。ランド＝城、カリフォルニア＝観覧車。時刻（パークの現地時間）で 昼 → 夕方（16:30〜）→ 夜（18:30〜）に自動で切り替え、夜は画面全体も少し暗めに。
- **装飾の背景**：雲（プランの提案・シート上部・お知らせ）、光ボケ（次の行き先カード）、ウェーブ（「この条件でプランを作る」ボタン）、淡いシルエット（閉園後のまとめ）。画像は `public/img/park/`（非公式のオリジナル装飾画像）。
- **マップ**：地図のパネルをヘッダーに重ねて画面の大部分を地図に。地図タイルは淡い青に。
- **ガラスのコントロール（iOS風 Liquid Glass）**：ボタン・チップ・セグメント・タブバー・シートは半透明＋背景ぼかし＋上端のハイライト＋細い縁の共通スタイル。主要ボタンは青い色付きガラス。タブバーは浮いたカプセル。「透明度を下げる」設定の端末では不透明に切替。
- **文字は最小限**：説明文の代わりにアイコン・色・線で示す（例：タイムラインの線の色＝前の場所からの移動の長さ）。
- カード左端の色線（Left Accent Border）は使わず、強調は塗り・影・背景画像で行う。
- **フォント**：`public/fonts/mplus-rounded-1c-{500,700,800}.woff2` はアプリで使う文字だけのサブセット（SIL OFL）。画面に新しい文言を足したら `scripts/build_fonts.py` で作り直す（手順はファイル先頭）。含まれない文字は端末のフォントで表示。

## 画面と使い方

| タブ | できること |
|---|---|
| **いま** | 上に「プランを共有／日付・時間／条件」。次に行く場所のカード（写真・待ち／徒歩／終了予定・理由タグ・次の予定に間に合うか・「乗った／別の候補／ルート」）、乗った数、ほかの候補（待ち短い／近い／人気）、お知らせ（再開・急に空いた） |
| **プラン** | 保存されたプラン（勝手には変わらない）。開くとすぐタイムライン：各行に時刻・待ち（参考）・**現在地からの徒歩**、左の線の色で前の場所からの移動の長さ。≡ で並べ替え、鍵で固定、○ で完了。下に「作り直す（今から／別の時刻から）」と条件のまとめ。条件シートは4タブ（基本／乗り物／ごはん／ショー）。2人共有では同じプランを共有 |
| **マップ** | 待ち時間色分けのピン（再描画せず差分更新・ズーム中の更新は後回しにして消えないように）、食事・ショー、**トイレ**（最寄りへのボタンつき）、現在地（「現在地を表示」ボタン）、次の目的地への点線。下端の1行バー（行き先・徒歩・待ち・ルート）だけで地図を広く使える |
| **探す** | 乗り物／食事／ショー／限定 の4区分。食事は「食べたいもの」検索（キーワード＋候補チップ、言い換えにも対応）で、該当メニューを強調して現在地から近い順に表示。「マップ」で該当店だけピン表示。一覧・フィルタ・並べ替え、詳細シート（「絶対乗る／おまかせ／乗らない」もここで切替）、ショーの回選択と夜の動き方 |

**プランの編集・提案**
- プランは「順番」として保存。勝手には並べ替えない。「乗った」でも順番はそのまま、時刻だけ再計算。
- **提案が出るのは2つのときだけ**：
  1. **自分が操作した直後**（≡ で並べ替え、「次に行く」、お知らせの「行く」）：操作はその場で反映し、動かしたものはその位置のまま、
     残りを動線よく並べ直せる場合だけ「動線を整える案」シートを出す（変更前→後・歩く分数・エリアの戻り回数。スクロールなしで1画面）。「反映」／「このまま」。
  2. **絶対乗るものが休止・再開したとき**：静かなカード「動線を整える案」だけ（タップで同じシート）。
- 並べ替え：≡ をドラッグ（乗り物・ごはん・ショー）。ごはんは置いた位置で時刻が決まる。ショーは開演時刻固定。
- 鍵ボタンで乗り物の位置を固定。作り直しても固定した乗り物はその位置のまま。
- 「編集」で × 削除、「＋追加」で自由に追加（動線のいい位置／次に行く）。乗り物の詳細からも「プランに追加／次に行く」・**乗る回数（−／＋）**。条件シートの乗り物タブでも「回数」に切り替えて、複数回乗りたいものだけタップで ×2 → ×3 → 1回。
  乗った回数は記録され（「済み 2回」・時刻つき）、回数はそれより少なくできない。一度乗ったものも詳細の「もう1回乗った」「もう1回プランに」や
  「＋追加」から2回目・3回目として追加できる。回数で指定した2回目以降は「絶対乗る」と同じ扱いで、1日が埋まっていてもおまかせの乗り物を外して
  閉園までに入れる（前の回から75分以上あける。どうしても入らない時だけ「入りきらない」と表示）。
- **条件シート**は「基本（開始・ペース・歩く量）／乗り物（次に行く・絶対／おまかせ／乗らない）／ごはん／ショー」の4タブ。どのタブも iPhone SE でスクロールなしで収まる。
- **間に合うかの知らせ（アイランド）**：次のごはん・ショーへ出発する15分前から、画面上部に小さなガラスのカプセル（アイコン・名前・出発時刻・残り時間のリング）。
  青＝間に合う、黄＝今出発、赤＝間に合わない。タップで「ルート／＋15分・＋30分・省略（ごはん）／次の回・見ない（ショー）」。始まるか完了で自動で消える。
- いま タブ：一番上に次の行動、その下に細い進み具合の帯、ほかの候補。休止中など行動不要の注意は1回だけ短いスナックバー。

当日の流れ：開いたら「いま」の大きなカードの通りに動く → 乗ったら画面下の大きな「○○ 乗った」→ 次のおすすめが自動で更新。

- **完了の記録**：押すと即完了（トーストで取り消し可）。完了したものはプランタブの「済み」に時刻つきで残り、
  タップすると確認してから未完了に戻せる（戻した後もトーストで再び完了にできる）。
- **再開・急減アラート**：休止していた施設の再開や、人気施設の待ち時間の急減（15分以上かつ3割以上）を画面上部に表示。
  「行く！」で次の行き先に固定。Androidは振動あり（iPhoneのSafariは振動非対応）。
- **待ち時間の推移**：アプリが取得した今日の実測値を端末に記録し、一覧に小さな折れ線＋↘↗、詳細に推移グラフ（推定は点線）を表示。
- **ボタン**：「乗った」「別の候補」「ルート」は次の行き先カードの中。
- **設定**：右上の歯車。現在地（GPS）のオン／オフ、待ち時間の更新、記録のリセットだけ。出典・テスト時刻・ホーム画面に追加の手順は「詳細」に格納。
- **デザイン**：絵文字は使わず線アイコン。iPhone SE（375×667）でも文字が切れないよう、名前は「・」の位置で改行。探すの乗り物は名前で検索できる。
- **写真**：Wikimedia Commons から実際のディズニーランドの施設・店舗・ショーの写真をサーバーが検索（他パーク・ロゴ・小画像は除外、
  作者・ライセンス表示）。見つからなければ Wikipedia の記事画像 → イラストタイルの順に代替。

## メール招待・共有プラン（Cloudflare Access）

設定 → 「メンバー招待・プラン共有」でメールアドレスを入力して招待すると、オーナー専用APIがCloudflare Accessの許可メールアドレスを追加します。初回はオーナーの現在の共有プランを自動保存します。端末のメールアプリで招待文が開くため、ユーザーが送信を完了します。自動メール配信サービスは使いません。

招待された人は招待メールのリンクからPIN認証してPark Naviに入り、ログイン情報に紐付く共有プランに自動参加します。共有コードを入力する必要はありません。従来のコード共有は折りたたみの「共有コードで参加」に残しています。

**初回の本番設定**：CloudflareアカウントのAccess Policies Read/Writeのみを付与したAPIトークンを、このPagesプロジェクト `dl-navi-1031` の**本番環境**の暗号化Secret `ACCESS_POLICY_API_TOKEN` に登録します。プレビューには管理権限のあるトークンを配置しません。GitHub、ブラウザ、ログにトークンを保存・表示しないでください。Secretが未設定なら招待は503となります。

招待APIはCloudflare Access JWTを署名・発行元・Audience・期限まで検証し、`shunsuke.aoki0913@gmail.com` だけがメール許可を変更できます。対象の既存Accessポリシー以外は変更しません。招待先のメールアドレスと共有ルームの紐付けは専用KVのみに保存します。

## 2人で共有

設定の「2人で共有」またはプランタブ下の「2人で同じプランを使う」→「共有を始める」で共有リンク（8文字コード）を作成し、相手に送る。
相手がリンクを開くかコードを入力すると参加。どちらかが「乗った」・順番・条件・ごはん/ショー・手入力の待ち時間を変えると、
もう1台も自動で更新（表示中は20秒ごとに確認、変更直後に送信）。「乗った」は合算、取り消しは新しい方が優先、設定は最後に変えた方が優先。
保存先は Cloudflare Workers KV（`dl-navi-1031-share`、バインディング `SHARE`）。保存するのはプランと記録のみ（位置情報は送らない）、7日で自動削除。

## データの扱い（偽装しないためのルール）

- **待ち時間**：ThemeParks.wiki（主）→ 失敗時 Queue-Times.com（予備）。Pages Function がエッジで60秒キャッシュし、
  画面表示中は3分ごとに自動更新。表示ラベル：`LIVE`（外部提供値）／`手入力`（公式アプリを見て入力）／`推定`（過去傾向の計画用の値）。
  15分以上古いデータは使わず推定に切り替え、バナーで明示。
- **ショー時刻**：APIから取得できればそれを使用（「APIの公式時刻」）。取得できない場合は事前情報として「要確認」と表示。手動修正可。
- **座標**：ThemeParks.wiki の施設座標を使用。取得できない場合は概略位置であることを表示。
- **徒歩時間**：直線距離×1.4 ÷ 分速70m の目安。**表示する徒歩はどこでも「いまの現在地から」**（いま・プラン・詳細・マップで同じ数字）。現在地が分からないときは「—」。
  プランの区間（前の場所→次）の長さは数字ではなくタイムラインの線で表示（緑＝近い、青＝ふつう、黄の点線＝遠い）。
- **トイレ**：マップに常に小さく表示、「トイレ」で大きく。右の丸ボタンで最寄りのトイレへ（徒歩・ルート）。位置は OpenStreetMap（`/api/restrooms`、Overpass API、エッジで1週間キャッシュ）。取れないときは各パークの概略位置（「概略」と表示）。
- **道案内（ルート）**：「ルート」は Google マップの徒歩ルートを開く（スマホのGPS現在地を出発点に指定）。アプリ内マップの「地図で見る」は目的地と現在地を点線で結んで表示。
- **一時休止**：休止中（DOWN）のアトラクションはタイムラインから外して「再開待ち」に表示し、再開を検知したら自動でプランに戻す。
- **位置情報**：「現在地を使う／現在地を表示」を押した時（または既に許可済みの場合）のみ取得し、端末内の計算にのみ使用（サーバー送信なし）。常時追跡（watchPosition）はせず、画面表示中だけ1回取得をマップでは60秒、他のタブでは3分に1回まで。
- **写真**：Wikimedia Commons（実物の写真・作者とライセンス表示）→ Wikipedia → イラストタイル。
- **進捗**：ブラウザの localStorage に保存（リロードしても保持）。

## 最適化アルゴリズム（概要）

`public/js/engine.js`（DOM非依存・テスト済み）

- **動線優先**。待ち時間の公式値は外れることが多いので**参考程度**（時刻の見積もりには使うが、順番はほとんど左右しない）。
  コスト＝徒歩×重み（歩く量の条件で 1.8／1／0.5 倍、**現在地からの最初の移動は2倍**）＋待ち×0.25＋**エリアの切り替え**（1回3分）
  ＋**いったん離れたエリアに戻る**（1回12分）＋ごはんの時刻のずれ＋ショーの遅刻＋閉園に入りきらない分。
- **何に乗るか と 順番** をまとめて最適化（`optimizePlan`）。乗り物の「価値」（人気＋優先度）からコストを引いたものを最大化。
  ペース（ゆったり6／ふつう9／たくさん14前後）を超えた分は価値を小さく数えるので、1日の詰め込み具合はペースで決まる。
- 探索：空き時間への挿入／外す／移動／入れ替え／区間反転／**2〜3件をまとめて移動**（同じエリアをひとかたまりのまま動かす）の局所探索＋
  ランダムに2つ外して組み直す反復（約0.6秒、同じ入力なら同じ結果）。
- **絶対乗る** は必ず含める（場所はコストで決める。閉園前90分は余裕のため避ける）。**次に行くところ** を決めたらそれを先頭に固定して残りを組む。
- **ごはん** は設定時刻の前後60分まで動かせる。時刻を自分で設定したごはんはその時刻で固定。ショーは公演時刻固定。
- 品質の目安（テスト）：乗り物どうしで「離れたエリアに戻る」は1日2回まで、最初の行き先は現在地から徒歩6分以内。
